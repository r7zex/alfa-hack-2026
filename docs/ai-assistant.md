# Кредитный ИИ-ассистент на Qwen

Ветка: `feat/AI-assistant`. Страница: `/#/assistant`.
Основной вариант использует локальный `qwen3.8:27b` через Ollama.
Платный API и ключ не нужны. Вычисления выполняются на вашем компьютере
или сервере. Модель загружается один раз и сохраняется в Docker volume.

## Запуск всего проекта с локальным Qwen

Создать `.env` из `.env.example`, если своего `.env` ещё нет.
В существующий `.env` добавить настройки ниже. Свой пароль БД сохранить.

```dotenv
QWEN_BASE_URL=http://127.0.0.1:11434/v1
QWEN_MODEL=qwen3.8:27b
QWEN_REASONING_EFFORT=auto
QWEN_REQUIRE_API_KEY=false
ASSISTANT_ENABLED=true
ASSISTANT_TIMEOUT_SECONDS=300
ASSISTANT_REQUESTS_PER_MINUTE=10
ASSISTANT_MAX_TURNS=50
```

```bash
docker compose -f compose.yaml -f compose.qwen.yaml up --build -d
docker compose -f compose.yaml -f compose.qwen.yaml logs -f qwen-init
```

Первый запуск скачивает модель. Приложение ждёт успешного завершения загрузки.
Готовность модели: `qwen-init` завершился с кодом 0. Затем открыть
http://127.0.0.1:8000/, войти клиентом и выбрать "ИИ-ассистент".
Для локальных синтетических аккаунтов можно установить `DEMO_AUTH_ENABLED=true`.
Контейнер приложения автоматически выполняет миграции Alembic.

Файлы `qwen3.8:27b` занимают около 18 ГБ по данным каталога Ollama:
https://ollama.com/library/qwen3.8:27b . Это размер файлов, а не полное требование
к оперативной памяти: при запуске нужны также контекст и ресурсы приложения.
Конфигурация допускает CPU, но время ответа зависит от оборудования.
Для более слабого компьютера можно выбрать `QWEN_MODEL=qwen2.5:7b` или
`QWEN_MODEL=qwen2.5:1.5b`. После замены модели нужно снова проверить отказы
и качество ответов. Ранее сохранённый `.env` сам не изменится: замените в нём
`QWEN_MODEL` явно, если хотите перейти на Qwen 3.8.
При нехватке памяти уменьшайте модель или длину контекста, а не отключайте проверки.

Остановка без удаления переписки и модели:

```bash
docker compose -f compose.yaml -f compose.qwen.yaml down
```

## FastAPI локально, Ollama установлен отдельно

Установить Ollama с https://ollama.com/download и запустить его.
Нужны зависимости проекта и настроенный `.env`.

```bash
ollama pull qwen3.8:27b
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Адрес Ollama по умолчанию: `http://127.0.0.1:11434/v1`. Ключ остаётся пустым.
Не публикуйте Ollama в интернет. В Docker файл `compose.qwen.yaml` сам заменяет
URL на `http://qwen:11434/v1`.

## Другой сервер Qwen

Провайдер заменяется через `QWEN_BASE_URL`, `QWEN_MODEL` и `QWEN_API_KEY`.
Для сервера, требующего ключ, установить `QWEN_REQUIRE_API_KEY=true`.
Ключ хранится только на backend. Нужен совместимый с OpenAI endpoint
`POST /chat/completions` с `response_format: {"type":"json_object"}`.
Адрес и название модели нельзя передать из браузера.

`QWEN_REASONING_EFFORT=auto` автоматически добавляет `reasoning_effort: "none"`
для тегов Ollama `qwen3.8` и `qwen3.8:27b`, включая namespace `library/`.
Это отключает thinking для классификации, генерации и проверки ответа,
чтобы бюджет вывода использовался для финального JSON. Поле reasoning_content
пользователю не показывается и не сохраняется в истории.
Для других алиасов можно установить `QWEN_REASONING_EFFORT=none`, а для
провайдера без поддержки параметра `QWEN_REASONING_EFFORT=omit`.
В режиме auto старые модели Qwen 2.5 получают прежний набор параметров.
Платные провайдеры не используются по умолчанию.

## Границы темы и данные

Разрешены кредитные продукты, проценты, погашение, залог, кредитная история,
документы для кредита и этапы кредитной заявки. Короткие уточнения разрешены
в контексте предыдущего кредитного вопроса. Посторонняя часть смешанного
запроса также приводит к отказу, даже если в тексте есть слово "кредит".

Сервер использует три уровня:

1. Обнаружение известных попыток сменить инструкции и отдельную
   классификацию вопроса с разрешённым кредитным контекстом.
2. Генерацию Qwen с фиксированными серверными инструкциями и текущим
   демонстрационным каталогом `app/credit_products.py`.
3. Независимую проверку готового ответа до его показа. Проверка получает
   отдельные инструкции и не использует диалоговую роль генератора.

Некорректный JSON, незавершённый вывод, неизвестные поля, внешние URL,
неподходящий ответ и ошибки проверок не пропускаются пользователю.
Отказы заранее заданы сервером, попытка сменить инструкции явно обозначается.
Сырые части ответа не стримятся в браузер до проверки.
Отказанные вопросы и ответы не добавляются в контекст следующей генерации.

Модель не имеет инструментов, доступа к БД, файлам, статусам заявок,
секретам и банковским операциям. Она получает только вопрос,
последние разрешённые сообщения, тип бизнеса и публичный демо-каталог.
Точный платёж рассчитывается существующим калькулятором продукта.
Внешние ссылки не генерируются; переходы ограничены тремя разделами кабинета.

Проверки на основе LLM вероятностные. Абсолютную защиту от всех формулировок
prompt injection нельзя обещать. После замены модели следует повторить
проверку реальным Qwen.

## Хранение и API

Переписка хранится в PostgreSQL отдельно для каждого пользователя и
восстанавливается после перезагрузки и нового входа. Черновик сообщения
хранится только в памяти вкладки. "Новый диалог" очищает текущую историю
аккаунта и увеличивает ревизию. Ответ старого запроса после очистки
не может вернуть удалённую переписку.

Все маршруты используют существующую HttpOnly сессию и клиентскую роль.
Изменяющие запросы требуют CSRF-токен. Клиент передаёт только текст,
ревизию и UUID запроса. Историю, system prompt и владельца сервер не принимает.
UUID обеспечивает повтор отправки без дублирования. В БД фиксируется аренда
обработки, поэтому вкладки и разные worker-процессы не генерируют одновременно
в одном диалоге. При ожидании Qwen соединение БД освобождается.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/assistant/conversation` | Своя история, ревизия, состояние |
| POST | `/api/assistant/messages` | `message`, `revision`, `request_id` |
| POST | `/api/assistant/reset` | Очистка своего диалога: `revision` |

Ограничения: вопрос до 2000 символов, по умолчанию 10 отправок в минуту
и 50 пар вопрос/ответ до нового диалога. В контексте максимум 6 разрешённых
пар и 12000 символов. При 503 доступна повторная отправка, при 409 нужно
обновить диалог. Ошибки не раскрывают ключ или сырой ответ провайдера.
Если локальная модель недоступна, подставного ответа нет.

## Проверки

```bash
python -m pytest -q
node --test tests/frontend*.test.mjs
python -m scripts.check_qwen
```

Первые две команды не требуют Ollama: транспорт модели заменяется тестовым,
а API-тесты используют настоящие серверную авторизацию, CSRF и SQL БД.
Третья команда проверяет реальную модель из `.env` на синтетических вопросах.
Запускать после загрузки Qwen. Пропущенный посторонний вопрос или отказ
на разрешённый вопрос даёт ненулевой код завершения.
