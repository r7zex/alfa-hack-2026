## Установка

Все источники и npm доступны. Taste и Vercel скопированы из официальных GitHub-репозиториев без выполнения их установщиков; сохранены все файлы соответствующих Skills. Это проектный эквивалент запрошенных `skills add`, без глобальных копий и ссылок. `install.sh` Taste не запускался и в проект не включён.

Impeccable установлен официальным CLI, сначала в изолированном временном каталоге, затем в проекте:

```sh
npm_config_ignore_scripts=true npm exec --yes --package=impeccable@4.7.0 -- impeccable install --providers=codex --scope=project
```

Параметр npm отключает lifecycle-скрипты зависимостей; явно выбранный CLI запускается. Хуки установлены в `.codex/hooks.json` и ссылаются на `.agents/skills/impeccable/scripts/impeccable`. Бинарник текущей платформы находится локально в `scripts/bin/` и исключён из Git вложенным `.gitignore`. В новом checkout launcher при необходимости скачает движок указанной в `scripts/VERSION` версии. Глобальные Skills не устанавливались. Кеш npm и кеш движка не являются глобальной установкой Skill.

## Проверки безопасности

- Проверены npm metadata, содержимое пакета Impeccable 4.7.0, JS shim, POSIX и Windows launchers, манифест хуков, операции загрузки и записи в исходниках движка. Для анализа исходников использован upstream commit `69c34b7c3d6267dfd783dacb9f58f04522656b2b`; это статический обзор, не доказательство соответствия релизного бинарника исходникам.
- Impeccable launcher выполняет нативный код. Новые загрузки требуют совпадения SHA-256 с release sidecar; это проверка целостности из того же источника, не независимая аттестация. Уже существующие бинарники и переменные `IMPECCABLE_BIN`, `IMPECCABLE_HOME`, `IMPECCABLE_DOWNLOAD_BASE` входят в границу доверия.
- Хуки `PostToolUse` и `Stop` запускают детектор, читают UI-файлы, могут создавать локальный кеш и обновлять Git exclude для служебных файлов. Первый запуск может скачать движок. Хуки не запускались на приложении во время установки.
- Taste: просмотрены точки запуска процессов, сетевые запросы, запись файлов, локальный HTTP/CDP-сервер и очистка временных профилей. Скрипты запускают Chromium, сохраняют отчёты и скачивают изображения/видео из открытых коллекций. Это не изолированные процессы: запускать на доверенных проектах, с доверенными путями вывода и временным каталогом. Автоматических хуков у Taste нет.
- Vercel: только `SKILL.md`, без исполняемых файлов и хуков. Каждый обзор требует загрузки изменяемых внешних правил с `raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`.
- Признаков намеренной кражи секретов или скрытого запуска установщиков в просмотренных точках не обнаружено. Это целевой статический обзор, а не полный аудит большого движка и браузерного runtime.

## Проверки работоспособности и ограничения облака

Проверены три уникальных `name` и три `SKILL.md`, отсутствие симлинков, корректность JSON, пути хуков, синтаксис всех `.mjs` Taste и shell launcher Impeccable. `engine-probe` вернул `impeccable-engine 0.1.16`; Taste вывел каталог секторов. Node 24 и Chromium доступны; CDP smoke test открыл локальную HTTP-страницу и прочитал её DOM. Загрузка актуальных правил Vercel по HTTPS успешна.

В этой облачной сессии нельзя подтвердить работу интерактивных меню локального клиента Codex, одобрить доверие к хукам через `/hooks` или управлять браузером на компьютере пользователя. После открытия нового checkout локально обновите список Skills/перезапустите Codex; если клиент поддерживает hooks, проверьте и одобрите проектный hook через `/hooks`. Наличие манифеста само по себе не подтверждает поддержку или запуск hooks облачным runner.

Навигация Chromium на `data:` URL в smoke test блокировалась политикой среды (`ERR_BLOCKED_BY_ADMINISTRATOR`); обычный локальный HTTP работал. Интерактивные режимы Impeccable `live`/`generate`, Windows launcher и полный дизайн-аудит приложения не проверялись. Их доступность зависит от браузера, клиента и сети. Изображения из внешних коллекций требуют доступа к соответствующим доменам.

Код приложения и зависимости не менялись. Тесты приложения не запускались, поскольку изменения ограничены Skills, хуками и этим отчётом.

В трёх Markdown references Impeccable нормализованы только завершающие пробелы и пустые строки для прохождения `git diff --check`.
