# Подключение авторизации

Формы регистрации и входа используют `app/static/js/auth.mjs` и серверный `/api/auth`.
Пароль отправляется только серверу, токен сессии хранится в HttpOnly cookie.
После обновления страницы аккаунт восстанавливается через `/api/auth/me`.
Профиль бизнеса и смена пароля сохраняются на сервере. Почта в профиле доступна
только для чтения. Для входа админа используется та же форма с почтой и паролем.
Кнопки входа без пароля видны только при `DEMO_AUTH_ENABLED=true`.

Описанные ниже localStorage, sessionStorage и вход без пароля относятся к исходному
фронтенд-прототипу. Текущая авторизация заменена серверной; создание и отправка заявок,
автосохранение и восстановление черновиков работают через API с серверной сессией.
Решения аналитика и файлы пока остаются локальным демо.
Контракт и проверки: [auth.md](auth.md).

# Делора: фронтенд кредитного кабинета

Интерфейс на HTML, CSS и JavaScript ES modules, без сборщика,
CDN и внешних зависимостей. FastAPI раздаёт сайт через app/main.py.
БД, модели, корневой Docker Compose и Python-зависимости не изменены.
Исходная точка ветки: main,
67dc3ad0aacbe60bd186eb20624ea99fa407973e.

## Запуск

Основной запуск из корня репозитория, в активном виртуальном окружении
с установленными requirements-dev.txt и настроенным .env из .env.example:

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000/. Этот же адрес доступен при запуске
основного Docker Compose. Отдельный процесс для фронтенда не нужен.
При настроенном .env фронтенд и /health открываются без работающей БД;
/ready отдельно проверяет доступность PostgreSQL.

Используйте этот запуск FastAPI и для локальной проверки фронтенда: он задаёт
корректные типы JavaScript-файлов независимо от реестра MIME в Windows.
Не открывайте index.html двойным щелчком через file://. Node.js и npm
для запуска сайта не нужны.

## Обновление и белый экран

Остановить предыдущий сервер. В терминале PyCharm, из корня проекта:

```bash
git switch feat/credit-cabinet-frontend
git pull --ff-only origin feat/credit-cabinet-frontend
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Перед первым запуском создать .env из .env.example, если .env ещё нет.
Существующий .env не перезаписывать. Открыть http://127.0.0.1:8000/
и один раз нажать Ctrl+F5. Для запуска через Docker после обновления кода
нужно пересобрать приложение: `docker compose up --build -d`.

304 Not Modified - ответ проверки браузерного кэша, сам по себе он не является
ошибкой JavaScript. В этой версии файлы фронтенда получают Cache-Control:
no-store; старые If-None-Match/If-Modified-Since не приводят к 304. Типы
.js и .mjs явно заданы как text/javascript. Остальные серверы раздачи файлов
могут использовать другие MIME-настройки, поэтому основной запуск указан выше.

До выполнения JavaScript HTML уже содержит экран загрузки. Ошибка импорта
модуля или синтаксиса показывает сообщение и раскрываемые подробности.
При выключенном JavaScript показывается отдельная инструкция. При открытии
через file:// выводится адрес HTTP-сервера. Эти сообщения помогают отличить
ошибку загрузки от проблемы с данными.

## Проверка сценария

1. На экране регистрации выбрать ИП или юридическое лицо. Для ИП используется
   12-значный ИНН, для юрлица 10-значный. Проверяются контрольные цифры.
   Указать вымышленные название/ФИО и почту. Аккаунт сохраняется в браузере.
   Два готовых синтетических аккаунта доступны кнопками "Демо: юрлицо"
   и "Демо: ИП". Их данные не нужно вводить вручную.
2. Открыть "Подбор кредита", выбрать продукт, изменить сумму и срок в
   калькуляторе. У овердрафта отдельно задать число дней использования суммы.
3. Нажать "Подать заявку", пройти шаги потребности, финансов, документов и
   проверки. Можно сохранить черновик и продолжить его после перезагрузки.
4. Для оборудования приложить предложение поставщика. Финансовый документ
   для ИП - налоговая декларация, для юрлица - бухгалтерская отчётность.
   Выписка по счёту общая. Загружать только синтетические PDF/JPEG/PNG до 10 МБ.
5. Отправить заявку, выйти, нажать "Войти как админ". В текущих заявках
   раскрыть строку, выбрать одобрение или отказ и отправить комментарий.
   Для отказа комментарий обязателен. При желании указать сумму для повторной
   подачи. Сохранённое решение переносит заявку в историю.
6. В истории найти заявку по ИНН. Войти обратно клиентом через "Вход" или
   кнопку соответствующего демо-аккаунта. В своей заявке увидеть решение,
   комментарий и хронологию. После отказа можно создать новую заявку с
   изменёнными условиями, сохранив предыдущую в истории.
7. После одобрения принять условия в демо. Это завершает учебный сценарий,
   не заключает реальный договор и не выполняет выдачу денег.
8. В личном кабинете изменить контакты и данные бизнеса, прикрепить документ,
   перезагрузить страницу и скачать сохранённый файл.

## Границы реализации

Это фронтенд-демонстрация. На main пока есть только инфраструктурные
/health и /ready, а продуктовые API пусты. Интерфейс не делает вид, что
заявки отправлены в банк, проверены по ФНС/БКИ или оценены ML-моделью.

- Регистрация и вход без пароля предназначены только для синтетических
  тестовых данных. Кнопка администратора не является защищённой авторизацией.
- Метаданные сохраняются в localStorage, текущая роль в sessionStorage,
  содержимое файлов в IndexedDB. Новый браузер или другой origin не увидит
  эти данные. Вкладки одного origin обновляются через storage event.
- Если localStorage/sessionStorage запрещены или переполнены, демо работает
  с временными данными в памяти и показывает предупреждение. Новые изменения
  в таком режиме теряются после обновления страницы. Существующие данные
  браузера при переходе во временный режим не удаляются.
- Клиентский интерфейс отбирает свои заявки и файлы. Это удобство демо,
  а не серверная защита доступа. Для production нужны серверные сессии,
  роли, проверка владельца, CSRF-защита и серверная валидация.
- Размер, сигнатура и расширение файла проверяются в браузере. Сохранённые
  документы скачиваются, но не вставляются в HTML. Серверная проверка,
  антивирус и контроль доступа относятся к будущему backend.
- У синтетических начальных заявок файлы не приложены. Два демо-документа
  профиля представляют собой текстовые образцы и скачиваются как .txt.
- Ставки, суммы, сроки и списки документов - наши учебные допущения,
  не условия реального банка. Оборотный кредит: 24%, 100 тыс.-5 млн рублей,
  3-36 месяцев. Оборудование: 21%, 300 тыс.-15 млн рублей, 6-60 месяцев.
  Овердрафт: 26%, 50 тыс.-2 млн рублей, срок лимита 1-12 месяцев.
- Для кредита применяется аннуитет: A = P*r / (1-(1+r)^(-n)),
  r = годовая ставка / 1200. Для овердрафта: проценты = использованная
  сумма * годовая ставка / 100 \* дни / 365. Это разные модели расчёта.
  Срок лимита овердрафта не считается сроком амортизации долга.
- Старый MVP откладывал кабинет аналитика. В этой ветке он реализован по
  новому запросу. Статусы интерфейса: draft, pending, approved, rejected,
  completed. Изменение отказанной заявки создаёт новую заявку.

Основания: исходный кейс, с. 6, 10-15 (веб-кабинет, синтетические данные,
внутрипродуктовый путь, допустимые упрощения); MVP, с. 2-3 (три продукта,
профиль ИП/ООО, шаги анкеты), с. 6 (предлагаемые API). Отдельные перечни
документов и численные условия в этих материалах не заданы.

## Точки подключения API

`app/static/js/store.mjs` - единственная граница хранения состояния.
Заменить реализацию репозитория HTTP-запросами после реализации backend,
сделать загрузку и мутации асинхронными, сохранив модули представления.
Не включать демо-вход администратора в production.

Предлагаемые в MVP маршруты: POST /api/login, GET/POST /api/applications,
GET/PATCH /api/applications/{id}, POST /api/applications/{id}/documents,
POST /api/applications/{id}/submit, POST /api/applications/{id}/accept.
Ветки регистрации, профиля и ручного решения аналитика требуют отдельного
согласования API. Это описание будущего подключения, эти маршруты здесь
не реализованы и не вызываются.

FastAPI раздаёт app/static по корневому пути / с index.html по умолчанию.
Путь к файлам вычисляется относительно app/main.py и не зависит от рабочей
директории процесса. Подключение статики находится после API-маршрутов;
будущие API-роутеры нужно регистрировать выше этого подключения. У клиента
маршруты используют #, поэтому отдельных серверных маршрутов для вкладок
не требуется. Подключение раздачи файлов не реализует продуктовые API.

## Структура

- app/static/index.html: точка входа.
- app/main.py: раздача фронтенда через общий FastAPI-сервер.
- app/frontend.py: явные MIME-типы JS/mjs и отключение кэша демо-ресурсов.
- app/static/styles.css: токены, компоненты, desktop/mobile и reduced motion.
- app/static/app.js: маршруты, оболочка, события.
- app/static/js/domain.mjs: продукты, формулы, проверки и экранирование.
- app/static/js/store.mjs: демо-репозиторий и IndexedDB.
- app/static/js/runtime.mjs: временное хранилище при запрете сохранения,
  совместимое клонирование JSON-данных и генерация идентификаторов.
- app/static/js/ui.mjs: общие компоненты, иконки, диалоги, уведомления.
- app/static/js/artwork.mjs: пути и общая разметка декоративных изображений.
- app/static/images/: 11 предоставленных иллюстраций в WebP.
- app/static/js/client.mjs: экраны клиента.
- app/static/js/forms.mjs: регистрация и пошаговая заявка.
- app/static/js/analyst.mjs: текущие заявки, решения, история и поиск.
- tests/frontend.test.mjs: проверки формул, ИНН и переходов демо-заявки.
- tests/test_frontend_serving.py: главная, ресурсы, независимость от рабочей
  директории и приоритет API-маршрутов.

## Проверки

Проверка HTTP-маршрутов, без работающей БД:

```bash
python -m pytest tests/test_infra.py tests/test_frontend_serving.py -q
```

Node.js 20+ используется только для unit-тестов:

```bash
node --test tests/frontend.test.mjs
```

Внешние JS-библиотеки, шрифты, модели, названия и логотипы банка не
используются. Знак Делоры и SVG-иконки написаны в этом фронтенде.

## Тёмное оформление

Фон #0e1014, боковая панель #111318, поверхности #181b22, границы #2b2f38,
основной текст #f4f5f7, вторичный #a2a8b4. Красные кнопки и акценты
сохранены. Тёмная тема применяется также к калькуляторам, диалогам,
документам, состояниям загрузки и кабинету аналитика.

Все 11 иллюстраций предоставлены пользователем, исходный рисунок не
изменён. WebP сохраняет прозрачность; общий размер файлов около 1,5 МБ.
График роста расположен на главной странице, выбор предложений - в
подборе, папка - в заявках, профиль - в личном кабинете. Кошелёк,
инструменты и портфель иллюстрируют три кредитных продукта и выбор
продукта в заявке. Здание показывает юрлицо в профиле, транспорт -
средства для развития бизнеса на странице оборудования. Две красные
волны чередуются между регистрацией и входом.

Декоративные изображения имеют пустой alt и не меняют названия кнопок
для скринридера. Предметные иллюстрации используют object-fit: contain,
ограничены размером контейнера и сохраняют пропорции. На узких экранах
иллюстрация заголовка переносится под текст. Волны служат фоном и могут
обрезаться по краям своего блока. Внешние запросы для загрузки изображений
не нужны. Данные и сценарии работы сохранены; backend не изменён.
