## API

Все изменения авторизованного сеанса требуют X-CSRF-Token и same-origin. Клиент хранит HttpOnly cookie, не query-token. Решение требует expectedVersion из действительно просмотренной карточки. Под блокировкой сравнивается version; устаревшая форма получает409 даже после повторной подачи заявки. Полная схема доступна в OpenAPI и `docs/openapi.json`.

- `/api/applications/{id}/workflow`, `/ml`, `/stream`: история, реальные ML-результаты, SSE.
- `/api/applications/{id}/tasks`, `/tasks/{task}/complete`: задачи; документ должен относиться к этой заявке и нужному типу.
- `/api/applications/{id}/messages`, `/messages/read`: изолированный банковский чат, request_id для повторов, read marker.
- `/api/analyst/applications/{id}/assign`, `/decision`, `/revoke`: назначение, решение и отзыв с мотивировкой.
- `/api/applications/{id}/signing-code`, `/offer/accept|decline|sign|disburse`: проверка прав/состояния/версии/hash/кода.
- `/api/loans`, `/{id}`, `/{id}/schedule.csv`: собственные выданные кредиты и график.
- `/api/notifications`, `/read-all`, `/{id}/read`, DELETE `/{id}`: уведомления.
- `/api/team`, `/invitations`, `/join`: сотрудники и capability-приглашение.
- `/api/analyst/analytics`, `/analytics.csv`, `/operations`: защищённые метрики и очередь.
- `/api/admin/integrations`, PUT `/{name}`, `/rules`, `/audit`, `/businesses/{id}/financial-profile`: настройки и аудит.
- POST `/api/products/recommendations`: цель, сумма, срок, выручка, расходы, обязательства; объяснимый подбор без «шансов одобрения».

## Mock-адаптеры

| Ключ | Смысл | Влияние |
|---|---|---|
| egrul | ЕГРЮЛ/ЕГРИП | Активность организации |
| fns | ФНС | Налоговые сведения |
| bki | БКИ | Синтетическая просрочка/обязательства |
| financials | Финансовые сведения | Проверка заявленных данных |
| turnover | Обороты | Синтетические поступления |
| issuance | Регистрация демо-выдачи | Выдача только при success |

Режимы: success, missing, negative, unavailable, timeout, malformed, transient. Последний даёт временную ошибку на первой попытке, затем успех. Независимые SourceSetting хранят режим, failure counter и open_until circuit breaker в PostgreSQL. Штатно3попытки, ограниченный backoff и timeout2с; circuit после3ошибок открыт15с. Настройки среды могут менять пределы в валидируемых диапазонах. Локальный mockScenario заявки управляет только БКИ и не ломает остальные компании. При technical failure сохраняются job/stage/attempts и безопасная причина; до ручного retry кредитное одобрение не возникает. Регистрация выдачи вызывается вне транзакции, затем состояние блокируется повторно; её результат фиксируется в истории только первой успешной выдачи.

## Аналитика

Статусы считаются по текущим строкам, воронка — по историческим событиям уникальных заявок. Стадия «Решение» включает approved/counter_offer/rejected; «запрос сведений» и маршрутизация не считаются кредитным решением. Auto share — доля кредитных решений с actor=null; повторные/старые версии не увеличивают знаменатель. Время до первого решения считается от первой отправки заявки; длительность worker — по завершённым jobs. Метрики описывают демо-БД и не являются банковской отчётностью. Аудит объединяет неизменяемые admin changes и события заявок; коды/токены/PDF в нём отсутствуют.
