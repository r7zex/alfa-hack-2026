# Model card: импортированный LightGBM

## Артефакт и назначение

Источник — предоставленный пользователем `LightGBM.joblib`. Исходный SHA-256 `1b9a0de1523b3c6bb64b269c960fafae169b570d9b056f3ea9198e63e3175f82`. Веса `artifacts/LightGBM_native.txt`, SHA-256 `8f5b6d91d91873e2bf8df6c2a0e0a796f076faedddf8dc88e82d28ff5393d386`. 450 деревьев, objective binary, 24 признака. sklearn Pipeline содержит только LGBMClassifier, без scaler/imputer. Конвертер фиксирует допустимый исходный hash, читает pickle opcodes пассивно и извлекает только native model string; ни приложение, ни конвертер не исполняют pickle/joblib.

Назначение интеграции — воспроизводимый технический инференс с аудитом входов и происхождения. Не используется как PD, вероятность одобрения или самостоятельное кредитное решение.

## Входы

Точный упорядоченный список — `FEATURE_NAMES` в `ml/imported_lightgbm.py` и manifest. Это финансовые показатели периода 2022: балансовые/потоковые значения и коэффициенты. API проверяет схему, лишние/отсутствующие поля, числовые типы, бесконечности, допустимые age/simplified. Частичные пропуски передаются native LightGBM как NaN; полностью отсутствующий профиль не скорится. Порядок JSON-полей не меняет результат.

`FinancialFeaturesProvider` получает отдельную запись FinancialProfile. Демо STABLE/STRESSED синтетические; их рублёвые показатели заданы в условных тысячах рублей, проценты/отношения/дни/годы описаны в provenance. Исходные единицы и точные определения обучающего датасета **не подтверждены**, поэтому даже «verified» означает аттестацию предоставившим администратором, а не доказанное совпадение с обучением. Поля анкеты кредита не подменяют эти 24 признака.

## Выходы и интерпретация

- `scores`: технический output класса 1, без бизнес-названия класса.
- `raw_scores`: logit native-модели.
- `contributions`: 24 вклада и base value; сумма проверяется против raw-score, logistic(raw-score) против score.
- `classification`, `threshold`, `probability_semantics`: отсутствуют/не установлены.
- Hash артефакта, признаки и provenance сохраняются в ModelPrediction по заявке/submission.

Нативный класс 1 сам по себе не доказывает bankruptcy/default. Метаданные sklearn encoder подтверждают числовую кодировку классов, но не экономический смысл. В модели есть class weighting; калибровка не предполагается. В интерфейсе вклад признака описывает raw-score модели, не причину одобрения/отказа.

## Валидация и метрики

В исходных метаданных обнаружены sklearn 1.8.0, 3-fold CV и best CV PR-AUC `0.3468188047579757`. Это **метаданные источника**, не воспроизведённая оценка и не holdout. Исходные данные/разбиение/порог/target mapping отсутствуют. Новые AP, ROC-AUC, Precision, Recall, F1, F2 на реальных данных не вычислялись и не выдумываются.

Фактически выполнены native-inference на двух синтетических профилях, воспроизводимость, проверка hash/schema/NaN/inf/повреждения, проверка вкладов, сохранение и чтение через API/UI. STABLE score `0.01761494455410715`; STRESSED `0.03764755346786663`. Разница не подтверждает качество модели или направление риска.

## Отдельное обучение

`ml/train_legal.py` использует binary log loss, 70/15/15 stratified seed42, кандидаты num_leaves 15/31/63, выбирает модель по validation AP, порог по validation F2, затем считает Train/Validation/Test метрики. Focal Loss не входит в основной эксперимент. Артефакт своего обучения — checksum JSON + native model, историческое имя `model_legal.joblib` сохранено для совместимости пути; pickle не читается. Imported и вновь обученная модели имеют разные схемы/семантику и не взаимозаменяемы.

## Отказ и риски

При недоступных/несовместимых признаках или повреждении весов сохраняется контролируемый `available=false`; кредитные демо-правила продолжают работу. Для банковского применения необходимы проверенный target, определения/единицы, out-of-time holdout, калибровка, fairness/drift и governance. Эти проверки не заявляются выполненными.
