## Сквозные API-сценарии

Для **ИП и ЮЛ** проверены: регистрация и роль, черновик, загрузка PDF, отправка с согласиями,
сохранённые проверки и демо-скоринг, решение аналитика, условия, принятие, сверка SHA256
договора, условная подпись, моделируемая выдача, logout/login и чтение того же результата.

Дополнительно: отказ, уточнения/редактирование/повторная подача, меньшая допустимая сумма,
отклонение предложения, отсутствие информации, отрицательный ответ, недоступность и
некорректность mock-источника, восстановление и история всех попыток. Прежнее одобрение
без версии условий проходит явный запрос уточнений и повторную проверку.

Проверены 404 для чужой организации/файла, 403 для роли и отсутствующего CSRF,
защита черновиков от аналитика, повторное использование и снятие PDF-вложения,
блокировка редактирования отправленного заявления и недопустимых переходов.
Версия предложения и подтверждение ознакомления обязательны.

PostgreSQL concurrency: четыре параллельных отправки дают одну оценку; четыре решения —
один успех и три 409; по четыре принятия/подписи/выдачи дают один набор записей и событий.
Есть уникальные ограничения предложения/договора/выдачи и проверка версии заявки.

## Воспроизведение

Основной запуск приведён в README. В проверенной облачной среде для сборки дополнительно
передавался публичный CA через BuildKit secret proxy_ca. Тестовые overrides меняли только
имя Compose-проекта/образа, пути env, порты и параметры новой БД; в product image
сертификаты и секреты среды не копировались.

Для PostgreSQL-тестов используйте только одноразовую БД:

```bash
TEST_AUTH_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@127.0.0.1:PORT/TEST_DB' \
  .venv/bin/python -m pytest -q tests/test_pipeline.py tests/test_analyst.py tests/test_auth.py
```

Fixture пересоздаёт таблицы. Реальные и сохранённые пользовательские БД для него не подходят.

## Фактические ограничения

* Источники, решения по правилам, договор и выдача демонстрационные. Реальных переводов нет.
* Обученные веса и реальный inference ЮЛ/ИП не проверены; inference ИП отсутствует в исходной ML-реализации.
  Основной workflow честно использует rule-based demo scoring для обоих типов.
* Qwen endpoint локально недоступен; точный ID qwen3.8:27b и реальный inference не подтверждены.
  Перенесённые тематические проверки, output review, лимиты и изоляция проверены mock-тестами.
* PDF/CMS проверяется offline; подлинность ФНС и отзыв сертификата не устанавливаются.
* Сквозной UI прогон выполнен на ЮЛ в Chromium; ИП покрыт сквозными API-тестами.
  Firefox/Safari и производственная нагрузка не проверялись.
* Обновление схемы проверено с main. БД, отдельно мигрировавшаяся чужими ветками,
  требует предварительного сопоставления alembic_version и backup.

Происхождение скопированного кода и все интеграционные изменения описаны в
[integration-audit.md](integration-audit.md). Исходные функциональные ветки и main служили
только источниками чтения. Автоматическое объединение с main не выполнялось.
