## Необходимая адаптация

* Заменены устаревшие Owner/owner_id в документах и scoring API на существующий Auth business_id.
* Роутеры подключены перед статическим mount. Все ORM-модели зарегистрированы в общей Base.metadata.
* Исправлена неоднозначность relationships к пользователю после добавления decider FK.
* Новые миграции исходных веток выстроены `e4 → f6 → e73 → e63 → a2026c001001`.
  Уже применявшиеся миграции main не изменялись; исходные ветки не редактировались.
* Решение аналитика проходит через общую state machine, сохраняет историю, создаёт версию предложения.
* Документы хранят bytes в БД; добавлены связь с организацией, тип и повторное использование.
  Снятие вложения удаляет связь с заявкой, не удаляя исходный PDF из организации.
* Постоянные браузерные решения и принятие предложения заменены API. Legacy тестовый
  browser adapter не используется после useServerAuth и не считается серверными данными.
* Docker включает ML/PDF-зависимости, libgomp1 и ml/, исправлены .dockerignore и права COPY
  для appuser; healthcheck проверяет готовность БД. Qwen учитывает настроенный HTTP proxy.
* Оборотный продукт ограничен 24 месяцами; frontend загружает актуальный каталог с сервера.
* Денежные финансовые показатели расширены до BigInteger без потери существующих значений.

## Новые компоненты

Транзакционная state machine, CAS и аудит событий, ProcessingRun, воспроизводимые mock-источники,
демо-политика для ИП/ЮЛ, рекомендации, reusable application_documents, CreditOffer,
DemoContract, DemoDisbursement; API/UI принятия/отказа/ознакомления/подписи/выдачи/повтора,
сквозные и PostgreSQL-конкурентные тесты, архитектурная и приёмочная документация.

## Что исходно отсутствовало или расходилось

В main нет серверного аналитика, документов и завершения сделки. Файлы/история/решения
частично существовали лишь в localStorage/IndexedDB. У ML нет весов и inference ИП;
входы анкеты несовместимы с коэффициентами банкротства. Новые роутеры исходных веток
не подключены; миграции ветвятся от старых ревизий. У Qwen не подтверждены доступность
endpoint и точный ID qwen3.8:27b. Эти ограничения не маскируются фиктивным inference.

Проверка refs до/после подтверждает отсутствие изменений всех исходных локальных refs;
push разрешён только в собственную ветку, PR в main не объединяется автоматически.
