## Эксперимент ЮЛ

Подготовка `prepare_legal(csv_path)` возвращает `X_eda, y_eda`, без обучения,
разбиения, сохранения CSV и запросов к источникам. Для исходного CSV используются
только V22–V42: точное переименование из ячейки 10 и исключение пяти коэффициентов.
Для подготовленного CSV используются числовые финансовые колонки с исключениями
ячейки 12 и идентификаторами/служебными полями, исключёнными по заданию. Обогащённые
поля используются только если присутствуют в подготовленном CSV. Сеть и автоматическое
обогащение отсутствуют. Пропуски и бесконечности не заменяются выдуманными значениями;
полностью пустые признаки исключаются, как в ноутбуке. Проверяются id, ИНН и бинарный target.
Выручка и выбросы не используются для удаления объектов.

Разбиение — два стратифицированных `train_test_split` с `random_state=42`:
сначала `test_size=0.15`, затем `test_size=0.15/0.85`. Сохраняется точная формула,
включая штатное округление sklearn (например, 139/31/30 на 200 строках).
Вес положительного класса — `sqrt(N_negative_train/N_positive_train)`.

Параметры: `n_estimators=400`, `learning_rate=0.05`, `num_leaves=31`,
`max_depth=-1`, `min_child_samples=30`, `reg_lambda=1.0`, `random_state=42`,
`n_jobs=-1`, `verbosity=-1`. Не подхватываются параметры других экспериментов
из глобального состояния ноутбука: используются явно заданные в задании базовые значения.

Сериализуемый `FocalObjective` точно воспроизводит градиент и гессиан последней ячейки,
включая clipping raw score, вероятности и нижнюю границу гессиана `1e-4`.
Gamma: 0…7 с шагом 0.5; выбор по validation Average Precision с той же сортировкой pandas.
Порог — максимум F2 на validation. Test участвует только в окончательных метриках.
Инференс: `expit(model.predict(X, raw_score=True))`, один sigmoid.
Нет SMOTE, scaler, импутации, калибровки или дополнительного обучения на validation/test.

Артефакт хранит модель, имена и порядок признаков, параметры, gamma, threshold,
вес класса, описание objective, версию формата, target, таблицу подбора и метрики
Train/Validation/Test: AP, ROC-AUC, Precision, Recall, F1, F2, confusion matrix,
размер и долю положительного класса. SHA-256 загруженного артефакта идентифицирует
использованные веса в результате скоринга.

Сохранение атомарное; существующие веса защищены от перезаписи без
`allow_replace=True` / `--allow-replace`. Перед публикацией артефакта сравниваются
предсказания с загрузкой joblib в новом Python-процессе. Objective и CLI используют
стабильное имя Python-модуля. Произвольные клиентские пути к joblib не принимаются HTTP API.

## Запуск и fallback

Из корня проекта, в окружении с существующими backend-зависимостями:

```bash
python -m pip install -r requirements-ml.txt
# Только после предоставления реального готового датасета:
python -m ml.train_legal data/datasets/legal.csv
```

Веса ЮЛ сохраняются в `artifacts/model_legal.joblib`; путь ИП зарезервирован отдельно
в `artifacts/model_entrepreneur.joblib`. ИП пока не обучается.

```python
from ml.eda_legal import prepare_legal
from ml.train_legal import predict_legal

X_eda, y_eda = prepare_legal("data/datasets/legal.csv")
result = predict_legal("artifacts/model_legal.joblib", X_eda.head(2))
```

Для ручного восстановления отсутствующих, повреждённых или несовместимых весов
вызовите `predict_legal(..., training_csv=..., allow_retrain=True)`.
Для замены существующего файла дополнительно требуется `allow_replace=True`.
Перед обучением проверяются входные признаки относительно CSV; после ожидания блокировки
артефакт проверяется повторно. Используется межпроцессная Linux `flock` на соседнем `.lock`.
Сохранение выполняется через временный файл и atomic link/replace.
Без подходящего CSV возвращается `ScoringError`, без случайных или постоянных score.
**HTTP-сервис не передаёт флаг повторного обучения и не запускает его на запросах.**

## Backend и моки

Роутеры: `POST/GET /api/scoring/{application_id}`;
`POST /api/documents/{application_id}` с multipart-полем `file`;
`GET /api/documents/{document_id}` и `GET /api/documents/{document_id}/content`.
Используются существующие `get_db`, `require_client`, CSRF и `get_owner`.
Заявки и документы проверяются по серверному owner; чужие идентификаторы дают 404.
Параметр `owner_id` от клиента не используется.

`ScoringService` загружает существующую заявку и бизнес, выбирает `legal`/`ie`,
получает сведения через DI, валидирует признаки и вызывает соответствующий предиктор
в threadpool. Сохраняет отдельную историю `ScoringResult`; GET возвращает последнюю
запись. Статус заявки не меняется, решение о выдаче кредита не принимается.
Score относится к target `bankrupt`, не к кредитному дефолту.

`ApplicationInputs` по умолчанию не преобразует суммы из кредитной анкеты в
коэффициенты 2022 года. Без подтверждённых финансовых признаков ЮЛ возвращается 422
`ml_unavailable`; ИП сообщает об отсутствии согласованного эксперимента.
Точка подключения реальных уже доступных признаков — DI `get_scoring_inputs`.

В `tests/ml_fixtures.py` доступны независимое тестовое FastAPI-приложение и:

- `MockSources`: ФНС/реестры для тестовых ЮЛ/ИП, неизвестного ИНН и недоступного источника;
  только ИНН, вид бизнеса, статус, дата регистрации и `source="mock"`.
- БКИ: clean/overdue/unavailable/error; каждый ответ помечен `mock`, доступные сценарии
  явно названы тестовыми, кредитный отчёт реального клиента не изображается.
- Финансы: фиксированные демонстрационные revenue/expenses/debt_payment с меткой `mock`.
  Финансовые коэффициенты 2022 года не достраиваются; обычный mock-путь даёт явную ошибку.
- `ModelInputs` и `mock_predictor`: только проверка успешного API/DB-контракта,
  provenance содержит `inference="mock"`; фиктивное значение не подменяет реальный ML.

Нет внешних запросов, ключей, токенов, отдельных mock-сервисов или случайного поведения
в ответах источников. Все подмены подключаются через `dependency_overrides` в тестовом приложении.

## PDF и подписи

Проверяется MIME, реальное чтение PDF и лимит 10 MiB. Имя файла нормализуется;
файловый путь клиента не используется. PDF-байты (PostgreSQL BYTEA), SHA-256,
метаданные, результат подписи и привязка к заявке сохраняются одной транзакцией.
Загрузка и чтение имеют контролируемые ошибки. Возвращаются отдельные статусы
invalid_pdf, unsupported_pdf (зашифрованный PDF), unsigned, invalid_signature,
unsupported_signature, signed. Для каждой разобранной подписи отдельно хранятся
cryptographic_valid, signed_bytes_intact, whole_document_covered и trust.
Статус `signed` означает наличие разобранной подписи; смотреть нужно на отдельные результаты.

Локальные Python pyHanko/CMS/cryptography: `allow_fetching=False`, пустые CRL/OCSP
и политика `NO_CHECK`. Не используются Java, VM, внешние API, CRL/OCSP.
Без переданных доверенных сертификатов trust=`unverified`. Явно переданные локальные
корни позволяют проверить цепочку, но не подтверждают автоматически принадлежность ФНС.
Всегда отдельно сообщается `fns_authenticity="not_established"`, `revocation_checked=False`.
Реальная цепочка ФНС не предоставлена; проверка квалифицированной подписи ФНС полностью
не подтверждена. Неподдерживаемые механизмы (в том числе недоступные библиотекам алгоритмы
ГОСТ) должны давать неполную/неподдерживаемую проверку. Проверки на реальном PDF ФНС не было.
Демонстрационное подписание кредитного договора кодом не реализовывалось.

## Неактивные точки подключения

`app/main.py` не изменялся: новые роуты в основном приложении **не доступны**.
При отдельном разрешении следующие строки потребуется добавить **до** существующего
`app.mount("/", ...)`, иначе catch-all frontend скроет роутеры:

```python
from app.api.scoring import router as scoring_router
from app.api.documents import router as documents_router

app.include_router(scoring_router)
app.include_router(documents_router)
```

Миграция `e73a91c042bf` имеет родителя `d821f90b7e36`, выполняется обычным
`python -m alembic upgrade head` и не требует импорта моделей в env.py.
Но текущий env.py импортирует только старый агрегатор `app.models.auth`.
Перед будущей **автогенерацией** нужно явно загрузить новые модели, иначе Alembic
может предложить удалить новые таблицы. При отдельном разрешении будущие импорты:

```python
import app.models.scoring_result
import app.models.document
```

Эти строки в старые файлы не внесены. Сравнение metadata проверено в отдельном
процессе с явным импортом новых моделей. При старте основного приложения также
не вызывается monkey patch или автоматическая регистрация.

Существующий Dockerfile не копирует `ml/` и не устанавливает `requirements-ml.txt`.
Подключение новых роутеров в контейнере потребует отдельного разрешения на эти
изменения; Docker/Compose не редактировались.
