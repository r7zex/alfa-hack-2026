# ML и демонстрационный скоринг

Перенесены `eda_legal.py`, `train_legal.py`, EDA/контракт ИП и проверки из
`feat/ml-scoring-mocks`. ЮЛ: подготовка признаков без утечки цели, стратифицированный
split, focal LightGBM, выбор порога, версии/хеши и проверка совместимости локальных joblib.
Обучение выполняется только явной CLI-командой, а не через API:

```bash
pip install -r requirements-ml.txt
python -m ml.train_legal --help
```

Готовых весов в репозитории нет. Признаки модели — финансовые коэффициенты 2022 года;
месячная выручка, расходы и сумма займа не подставляются вместо этих коэффициентов.
Inference ИП в исходной реализации не готов и возвращает контролируемую ошибку.
`POST /api/scoring/{application_id}` сохраняет независимую оценку банкротства только
при наличии корректных артефактов и доверенного поставщика признаков. Иначе возвращает
422 `ml_unavailable`; фиктивного ML-прогноза нет. Загрузка joblib от клиента запрещена.

Основной конвейер автономен: `credit_policy.evaluate` считает явно обозначенные
демонстрационные баллы для ИП/ЮЛ, долговую нагрузку и рекомендацию по правилам продукта.
Это не вероятность банкротства, не PD кредита, не банковская модель и не политика Альфа-Банка.
Результаты и происхождение источников сохраняются в processing_runs.

`pytest -q tests/test_scoring.py tests/test_signatures.py` проверяет переносимые контракты,
синтетические артефакты, валидацию признаков и PDF/CMS. Реальная точность модели на
производственных данных не установлена. Qwen — отдельно подключаемый помощник;
он не заменяет скоринг и не управляет заявками.
