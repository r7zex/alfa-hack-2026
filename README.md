# Делора — кредитный кабинет Alfa Hack 2026

Учебный кредитный конвейер для ИП и юридических лиц: подбор продукта → анкета и PDF →
mock-проверки и демонстрационный скоринг → решение аналитика → предложение → принятие →
демо-договор → моделируемая выдача. Все постоянные данные хранятся в PostgreSQL.
Реальные кредиты, банковские операции и обращения в государственные реестры не выполняются.

## Запуск

Требуются Docker Engine/Desktop и Compose v2. Существующий `.env` не перезаписывайте.

```bash
cp .env.example .env  # только если файла ещё нет
# Для локальных синтетических аккаунтов установите DEMO_AUTH_ENABLED=true в .env.
docker compose up --build -d
docker compose ps
curl -fsS http://127.0.0.1:8000/ready
```

Сайт: http://127.0.0.1:8000/; OpenAPI: http://127.0.0.1:8000/docs.
В образ входят ML-библиотеки и проверка PDF; миграции выполняются перед запуском API.
Qwen и обученные веса для основного сценария не нужны. Docker healthcheck проверяет `/ready`.
PostgreSQL сохраняет пользователей, сессии, файлы, решения, переписку и сделки в `postgres_data`.
`docker compose down` сохраняет volume; не используйте `down -v` для сохранённых данных.
Порт меняется через `APP_PORT`. Для отдельной тестовой конфигурации поддерживается
`APP_ENV_FILE=/absolute/path/to/test.env` и `docker compose --env-file ... -p отдельный-проект ...`.

## Аккаунты и проверка

При `DEMO_AUTH_ENABLED=true` на входе доступны «Демо: юрлицо», «Демо: ИП» и
«Демо: администратор». Они используют существующую серверную авторизацию без пароля,
а не браузерные роли. Не включайте этот режим на общей установке с реальными данными.
Для обычного администратора: `docker compose exec app python -m app.admin --help`.
Пароли обычных пользователей задаются при регистрации. ИНН синтетических аккаунтов:
юрлицо `9900000017`, ИП `990000000115`. Используйте только вымышленные сведения и PDF.

1. Войдите клиентом, выберите продукт и создайте заявку. Черновик сохраняется через API.
2. Для положительного сценария: сумма 1 000 000 ₽, срок 12 месяцев, выручка 1 500 000 ₽,
   расходы 700 000 ₽, другие платежи 10 000 ₽; сценарий «Источники доступны».
3. Приложите PDF выписки и отчётности ЮЛ / декларации ИП. Для оборудования нужен счёт поставщика.
4. Подтвердите синтетические данные и демо-проверки, отправьте заявку.
5. В другом сеансе войдите аналитиком. Просмотрите проверки и документы, одобрите заявку.
6. Клиент обновляет статус, принимает предложение, читает договор, подтверждает ознакомление,
   условно подписывает и завершает демонстрационную выдачу. После reload результат сохраняется.

## Продукты и решения

| Продукт | Сумма, ₽ | Срок, мес. | Демо-ставка |
| --- | ---: | ---: | ---: |
| Оборотный кредит | 100 000–5 000 000 | 3–24 | 24% |
| Оборудование | 300 000–15 000 000 | 6–60 | 21% |
| Овердрафт | 50 000–2 000 000 | 1–12 | 26% |

Каталог загружается в существующий frontend с `/api/products`. Подбор сначала исключает
недопустимые суммы/сроки, затем учитывает цель. Можно выбрать любой допустимый продукт.
Демо-политика ограничивает обслуживание долга 50% свободного денежного потока, учитывает
прочие обязательства, документы и результаты mock-источников. Возможны рекомендация
одобрения, отказа, уточнений, меньшей суммы и техническая ошибка с повтором.
Окончательное решение принимает аналитик; неполные, отрицательные и технически
неуспешные проверки блокируют одобрение. Овердрафт: ежемесячные проценты и возврат
основного долга в конце срока; при оценке доступности резервируется также principal / months.
Баллы риска не являются PD кредита, вероятностью банкротства или политикой Альфа-Банка.

## API

Все изменяющие операции после входа требуют cookie сессии и `X-CSRF-Token` из
`GET /api/auth/csrf`. Исходные login/register/profile API сохранены.

| API | Назначение |
| --- | --- |
| `GET /api/products`, `/api/products/recommendations` | Каталог и объяснимый подбор |
| `GET/POST /api/applications` | Список организации и создание черновика |
| `GET/PATCH /api/applications/{id}` | Просмотр/редактирование черновика и уточнений |
| `POST /api/applications/{id}/submit` | Согласия, проверки и передача аналитику |
| `GET /api/applications/{id}/workflow` | События, документы, оценки, предложения, договор и выдача |
| `POST /api/applications/{id}/retry` | Безопасный повтор после технической ошибки |
| `GET/POST /api/documents` | Документы организации, повторно используемые в заявках |
| `POST /api/documents/{application_id}` | Загрузка PDF до 10 MiB с проверкой структуры и подписей |
| `GET /api/documents/{id}[/content]` | Метаданные / исходные PDF из PostgreSQL |
| `GET /api/analyst/applications`, `/organizations` | Фильтры по компании, автору, ИНН, email и статусу |
| `POST /api/analyst/applications/{id}/decision` | `approved`, `rejected`, `needs_info`, комментарий, alternativeAmount |
| `POST /api/applications/{id}/offer/{action}` | `accept`, `decline`, `sign`, `disburse`; обязательный offer_id |
| `POST/GET /api/scoring/{id}` | Отдельный контракт ML-оценки банкротства, если доступны веса/признаки |
| `/api/assistant/conversation`, `/messages`, `/reset` | Изолированная переписка с Qwen |

Примеры тел запросов: [docs/requests.http](docs/requests.http), подробная схема — OpenAPI.
Ошибки доступа к чужой заявке/документу возвращают 404; неверная роль — 403;
недопустимое состояние/устаревшее предложение — 409; неполные данные — 422.
Документы черновиков недоступны аналитику. Сотрудники одной организации используют
общие заявки; между разными организациями доступ изолирован.

## Хранение и конкуренция

Сессии HttpOnly/SameSite, CSRF и Argon2 используются из `main`; второй системы входа нет.
Изменения заявки блокируют её строку PostgreSQL и проверяют версию перед записью.
История содержит время, пользователя (null для системы), причину и старое/новое состояние.
Отправка, принятие, подписание и выдача повторяемы без дополнительных побочных эффектов;
двойное решение отклоняется. У договора уникальный offer_id, у выдачи уникальны заявка и
предложение. Принятие сохраняет согласие и версию; подпись сверяет SHA-256 текста договора.
Все связанные записи фиксируются одной транзакцией. Состояния старых заявок не переименованы;
старый `pending` проверяется при решении, `completed` отображается как ранее завершённый
сценарий без фиктивной выдачи. Для старого `approved` без предложения аналитик в истории явно запрашивает
уточнения; клиент дополняет документы и повторно проходит обычную проверку/решение.
Условия, договор и выдача не создаются задним числом.

Один head Alembic: `a2026c001001`. Миграции `main` не изменены. Новые миграции функциональных
веток включены последовательно только в этой ветке; существующие заявки и аккаунты сохраняются.
Установка рассчитана на обновление `main`, а не базы, уже независимо обновлённой чужой веткой.
Перед таким переносом схемы нужно отдельно сопоставить её alembic_version и сделать backup.

## Qwen и ML

`ASSISTANT_ENABLED=false` отключает ассистента, остальные страницы работают.
При включении задайте `QWEN_BASE_URL`, `QWEN_MODEL`, при необходимости `QWEN_API_KEY`.
По умолчанию указан запрошенный `qwen3.8:27b`, но его точный ID должен присутствовать
в `/v1/models` вашего провайдера. Локальный endpoint в этой среде недоступен;
реальный inference и наличие этого ID не подтверждены. [docs/ai-assistant.md](docs/ai-assistant.md).
Ассистент не получает инструменты выполнения операций и не принимает кредитные решения.

ML-код и тесты перенесены из `feat/ml-scoring-mocks`. Весов нет; inference ИП пока не
реализован в исходной ветке. Поэтому автономный конвейер использует только явно обозначенные
правила для обоих типов бизнеса. Финансы анкеты не преобразуются в финансовые коэффициенты
2022 года модели банкротства. Обучение не запускается в HTTP-запросах. [ml/README.md](ml/README.md).

## Разработка и тесты

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt -r requirements-ml.txt
docker compose -f compose.yaml -f compose.dev.yaml up -d db
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
pytest -q
node --test tests/frontend*.test.mjs
```

Для проверки блокировок задайте `TEST_AUTH_DATABASE_URL=postgresql+psycopg://...`
**отдельной одноразовой тестовой БД** и выполните `pytest -q tests/test_pipeline.py`.
Этот fixture пересоздаёт таблицы; никогда не направляйте его на сохранённые данные.
SQLite используется только в быстрых тестах. Интеграционные результаты и реальные команды:
[docs/acceptance.md](docs/acceptance.md). Архитектура: [docs/design.md](docs/design.md).
Аудит веток и происхождение кода: [docs/integration-audit.md](docs/integration-audit.md).
